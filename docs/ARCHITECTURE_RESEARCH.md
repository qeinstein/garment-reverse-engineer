# Architecture Research: Atelier & Seamer-Studio Integration

This document records the architectural and geometric findings from deep inspection of `ahzs645/atelier` and `ahzs645/seamer-studio` (and its submodules `@seamer/body-model` / `@seamer/avatar`).

All statements in this document are strictly categorized as **[VERIFIED FACT]** (directly inspected from source code, schemas, and tests) or **[DESIGN DECISION]** (architectural conclusions for our system).

---

## 1. How Seamer Represents a Pattern

### [VERIFIED FACT] Pattern Schema & Core Structure
Defined in `@seamer/pattern-model/src/pattern.ts` (root interface: `Pattern`):
* **Units**: All 2D plan coordinates, offsets, and seam allowances are in **millimeters (`mm`)**. The 3D viewport and simulator convert coordinates from millimeters to meters (`m`) by dividing by `1000`. Angles are in degrees (`deg`) or radians (`rad`).
* **Root Fields**:
  * `id: string` (UUID)
  * `name: string`, `description: string`
  * `lengthUnit: 'inch' | 'cm' | 'mm'`
  * `angleUnit: 'degrees' | 'radians'`
  * `seamAllowance: number` (default pattern allowance in mm, e.g. `12.7`)
  * `points: ConstrainablePoint[]`: Drafting point registry.
  * `paths: ConstrainablePath[]`: Geometric paths connecting points.
  * `pieces: Piece[]`: 2D/3D garment panel definitions.
  * `seams: Seam[]`: Sewing pairings linking edges.
  * `materials: Material[]`: Fabric physics and rendering properties.
  * `variables: Variable[]`: Parametric variables driving drafting formulas.
  * `measurements?: Measurement[]`: 2D plan measurement annotations.
  * `assembly?: Assembly`: Ordered sewing timeline (`AssemblyStep[]`) specifying which seams close and how many settle frames occur.
  * `body: Body`: Wearer measurements and avatar parameters.
  * `layers: Layer[]`: 2D layer organization (visibility, locking).
  * `settings3d: PatternSettings3D`: 3D rendering, avatar display, gravity, ambient occlusion, simulation settings.
  * `viewMode: '2d' | '3d' | 'both'`

## 2. How Panels / Pieces are Represented

### [VERIFIED FACT] Piece Interface
In `@seamer/pattern-model/src/pattern.ts`, `interface Piece`:
* `id: string`: Unique piece identifier (e.g., `Piece_0`).
* `name: string`: Human-readable label (e.g., `Front`, `Back`, `Sleeve_L`).
* `type: 'dynamic' | string`: `'dynamic'` designates a closed, simulatable cloth piece.
* `materialId: string`: References a `Material.id` in `pattern.materials`.
* `origin: NamedVector`: Piece-local origin in 2D mm (`{ id, name, x, y }`).
* `originPoint: string`: ConstrainablePoint ID anchoring the piece origin.
* `position: { x: number; y: number }`: Placement of the piece on the 2D drafting canvas (in mm).
* `rotation: number`: Canvas rotation in degrees.
* `grainVector: NamedVector`: Fabric grain line vector (default `{ x: 0, y: 1 }`).
* `mainPaths: PiecePath[]`: Ordered boundary loop of edges defining the outer perimeter.
* `internalPaths: PiecePath[]`: Internal lines such as darts, internal seam lines, fold lines (`foldAngle`, `showIn3d`).
* `firstEdgeSymmetry?: boolean`: When true, `mainPaths` describes half the piece drafted on one side of the first edge, and the full outline is generated by mirroring across that edge ("cut on fold").
* `settings3d: PieceSettings3D`: 3D placement, pinning, simulation flags, and cached settled positions.
* `legacyGeometry?: LegacyPieceGeometry`: Carries raw interchange polylines (`boundary`, `sewLines`, `cutBoundary`, `notches`).

## 3. How Edge Geometry is Represented

### [VERIFIED FACT] ConstrainablePoint, ConstrainablePath, and PiecePath
In `@seamer/pattern-model/src/pattern.ts` and `src/utils/patternGeometry.ts`:
1. **`ConstrainablePoint`**:
   * `id: string`, `name: string`, `x: number`, `y: number` (resolved coordinates in mm).
   * Optional `constraint: PointConstraint` for parametric drafting:
     * `offset` (dx, dy formulas from an anchor point)
     * `lengthAngle` (length and angle formulas from an anchor point)
     * `sliding` (point sliding along a path)
     * `mirror` (reflection across an axis path)
     * `intersection` (intersection of two rays from anchor points).

2. **`ConstrainablePath`**:
   * `id: string`, `name: string`, `pathType: 'line' | 'curve' | 'referenced'`
   * `pathPoints: PathPoint[]`: Ordered anchor points where each `PathPoint` has:
     * `id: string`: references a `ConstrainablePoint.id`.
     * `handle?: BezierHandle`: Tangent control handles for cubic Bézier curves:
       * `v1: { x: number; y: number }`: incoming control point offset in mm relative to the anchor.
       * `v2: { x: number; y: number }`: outgoing control point offset in mm relative to the anchor.
   * Straight lines are represented by `pathPoints` without `handle`.

3. **`PiecePath` (Boundary Edge)**:
   * `id: string`: Unique edge ID used for seam referencing (e.g. `PP_0_1`).
   * `path: string`: ConstrainablePath ID supplying the underlying curve/line.
   * `from: string`, `to: string`: ConstrainablePoint IDs specifying the start and end of this edge span.
   * `reversed: boolean`: Whether the path direction is reversed relative to path order.
   * `notches: Notch[]`: Alignment notches along the edge.
   * `wire?: WireChannel`: Stiffener definition (boning, hoop, wire channel; `mode: 'stitched' | 'threaded'`, `diameter`, `stiffness`).
   * `seamAllowance?: number`: Per-edge seam allowance override in mm.

## 4. How Seams are Represented

### [VERIFIED FACT] Seam Interface & Matching
In `@seamer/pattern-model/src/pattern.ts`:
```ts
export interface SeamRef {
  id: string; // PiecePath id
  mirrored: boolean;
  reversed: boolean;
}

export interface Seam {
  id: string;
  name: string;
  label?: string | null;
  fromPaths: SeamRef[];
  toPaths: SeamRef[];
}
```
* **Targeting**: `fromPaths` and `toPaths` directly reference `PiecePath.id` (not `ConstrainablePath.id` or point IDs).
* **N-to-M Stitching**: A seam can join 1 edge to 1 edge, 1 edge to multiple edges, or multiple edges to multiple edges (e.g. waistband to skirt front panels across darts).
* **Orientation**: `reversed: boolean` controls whether the stitch sequence along the edge is inverted.
* **Mirrored Instances**: `mirrored: true` targets the symmetric `#M` copy when pieces are duplicated as left/right pairs.
* **Particle Correspondence**: During simulation preparation (`computeSeamEdgeIntervals` in `@seamer/cloth-sim`), the total length of `fromPaths` and `toPaths` is computed. The solver allocates equal numbers of particle subdivisions along both sides (using largest-remainder distribution) so particles can be connected 1-to-1 with zero-rest-length distance constraints.

## 5. How 2D Pieces Become 3D Simulated Cloth

### [VERIFIED FACT] Triangulation & Simulation Pipeline
Inspected in `@seamer/cloth-sim/src/geometry/boundary.ts` and `src/build.ts`:
1. **Loop Stitching**: `stitchLoop(edges)` takes the `PiecePath` polylines and matches endpoints within a tolerance (default 1.0 mm) to form a closed outer loop.
2. **Seam Interval Allocation**: `computeSeamEdgeIntervals(pattern)` enforces identical particle counts on opposite sides of every seam.
3. **Resampling**: The boundary loop is resampled at `particleDistance` (default 10 mm), tagging each particle with its owning `PiecePath.id`.
4. **Constrained Delaunay Triangulation**: Delaunator computes 2D Delaunay triangulation inside the outer loop. Slivers and external triangles are rejected.
5. **3D Positioning**: `arrangeParticles` applies the piece's `PieceSettings3D.arrangement` (or maps onto `savedPositions` if a settled cache exists).
6. **Constraint Generation**:
   * **Stretch constraints**: Distance constraints along triangle edges, anisotropic compliance based on orientation relative to `grainVector`.
   * **Bend constraints**: Dihedral constraints between opposite vertices of adjacent triangles. Edges are colored into conflict-free groups for parallel Gauss-Seidel relaxation.
   * **Seam constraints**: Distance constraints between paired particles on opposing seam edges.
7. **WebGPU XPBD Solver**: Solves position-based dynamics in compute shaders against avatar collision meshes.

## 6. What Initial 3D Placement Information is Required

### [VERIFIED FACT] PieceArrangement & Settings3D
In `@seamer/pattern-model/src/pattern.ts` and `@seamer/cloth-sim/src/geometry/arrangement.ts`:
```ts
export interface PieceArrangement {
  mode: 'curved' | 'flat' | string;
  cylinderName: string; // e.g. "Torso", "LeftUpperArm", "RightUpperArm", "LeftUpperLeg", etc.
  uDegrees: number; // circumferential angle around cylinder (0 = front, 180 = back, 90 = left)
  v: number; // axial position along cylinder (0 = start bone, 1 = end bone)
  uOffsetMm: number;
  vOffsetMm: number;
  radialOffsetMm: number; // outward offset from body surface (mm)
  use2DPosition: boolean; // if true, lays flat in 3D plane at z=0.3m
  matrixWorld: number[]; // 16-float column-major group transform
  position: number[]; // 3-float [x, y, z] in meters
}
```
* **Available Cylinders**: Fitted to the avatar skeleton from `@seamer/body-model/models/base_model.json`:
  * `'Torso'`
  * `'Neck'`
  * `'LeftUpperArm'`, `'RightUpperArm'`
  * `'LeftLowerArm'`, `'RightLowerArm'`
  * `'LeftShoulder'`, `'RightShoulder'`
  * `'LeftUpperLeg'`, `'RightUpperLeg'`
  * `'LeftLowerLeg'`, `'RightLowerLeg'`
* **Curved vs Flat**:
  * `'curved'`: Rolls the 2D panel circumferentially around the cylinder radius.
  * `'flat'`: Places the panel tangent to the cylinder surface at `(uDegrees, v)`.
* **Normals**: `flipNormals: boolean` on `settings3d` flips outward normal (standard for back panels).
* **Warm-Start / Saved Positions**: `PieceSettings3D.savedPositions` is a flat array of stride 5 (`[x2d_mm, y2d_mm, x3d_m, y3d_m, z3d_m]`). If provided, `buildSavedCloth` or `reuseSavedDrape` directly initializes 3D particle positions from this settled state without requiring cylinder re-arrangement.

## 7. How Measurements & Avatar Sizing Work

### [VERIFIED FACT] Avatar Architecture
Inspected in `@seamer/avatar` and `@seamer/body-model`:
* **Body Model**: Statistical PCA shape model based on 69 anthropometric measurements (`female_model.json`, `male_model.json`).
* **Deformation**: Shape coefficients deform the baseline vertex mesh; linear blend skinning (LBS) skins vertices to skeleton bones.
* **Cylinders & Landmarks**: The 12 arrangement cylinders and 119 arrangement points automatically adjust their positions and radii as the avatar changes measurements.
* **Pattern Body Record**: `pattern.body.fields` contains key-value pairs (e.g. `age`, `height`, `weight`, `chestGirth`, `waistGirth`, `hipGirth`). When `useBodyMeasurementsForSizes` is enabled, variables and point constraints can read these fields directly.

## 9. Minimum Information External Reconstruction Must Provide

### [VERIFIED FACT] Minimum Requirements for Seamer Compatibility
To successfully display in 2D, edit in CAD, and simulate in 3D without errors:
1. **2D Piece Boundaries**:
   * Ordered sequence of edges (`PiecePath`).
   * Each edge must have resolved `from` and `to` point coordinates forming a closed, non-self-intersecting loop polygon.
   * Edges can be straight lines (2 points) or cubic Bézier curves (points with incoming `v1` and outgoing `v2` tangent offsets).
2. **Seam Connectivity**:
   * Explicit pairs of `fromPaths` and `toPaths` referencing `PiecePath` IDs.
   * Appropriate `reversed` flag so particle chains align in the same direction.
3. **3D Initial Placement**:
   * At least one of:
     * Cylinder arrangement (`cylinderName`, `uDegrees`, `v`, `mode: 'curved' | 'flat'`).
     * OR 3D translation/transform (`position` / `matrixWorld`).
     * OR vertex cache (`savedPositions` stride 5).
4. **Material Parameters**:
   * At least one material with stretch warp, stretch weft, bend stiffness, and surface density (weight in g/m²). Default fallbacks can be supplied.

## 10. Design Decisions for GarmentIR v0

### [DESIGN DECISION] Canonical Representation Principles
1. **Strict Neutrality**: GarmentIR is **NOT** Seamer, **NOT** Atelier, **NOT** ReWeaver, and **NOT** CLO. It uses semantic names (`panels`, `edges`, `seams`, `grain_line`, `placement_3d`, `evidence`, `uncertainty`).
2. **First-Class Uncertainty & Hypotheses**:
   * Every inferred feature carries a confidence score `[0.0, 1.0]`.
   * Unobserved or ambiguous features (e.g. rear closure, internal facings) support `hypotheses: AlternativeHypothesis[]`.
3. **Evidence & Provenance Tracking**:
   * Every panel, edge, seam, and detail can link back to source media via `provenance: { source_media_ids, frame_indices, observed_vs_inferred, notes }`.
4. **Human Correction Layer**:
   * Retains user modifications and overrides explicitly, enabling personalization and model fine-tuning data collection.
5. **Decoupled 3D Representation**:
   * Accommodates both semantic body-part placements (e.g. torso front/back, sleeves) AND explicit 3D rigid transforms / correspondence meshes from reconstruction models (such as ReWeaver or GarmentRec).
6. **Seamless Adapter Translation**:
   * `seamer-adapter` compiles GarmentIR into a valid Seamer `Pattern` without leaking Seamer types back into GarmentIR.
